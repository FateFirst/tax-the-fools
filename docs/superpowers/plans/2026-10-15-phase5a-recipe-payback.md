# Tax The Fools: Phase 5a (Recipe Database and Payback) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task by task.
> Requirements, interfaces and required tests. Implementers write the code test-first against the spec.

**Goal:** Show the Tailoring recipes each character hasn't learned, with the cost to get them and how many crafts each takes to pay back. It shows on the Crafting page, on pattern tooltips, and as Recipe deals.

**Architecture:**
- **Built-in data:** generated by `tools/make-recipes.py` into `recipedata.lua`.
- **Pure rules:** `recipes.lua`.
- **Learning in game:** read-only, in `recipes_learn.lua`.
- **UI:** additions to `ui_craft.lua`, `tooltip.lua`, `deals.lua`, `ui_deals.lua` and `options.lua`.
- **Plumbing:** wired through `core.lua`.

**Spec:** `docs/superpowers/specs/2026-10-15-phase5a-recipe-payback-design.md`.

## Global Constraints

- Everything in the phase 4 plan's Global Constraints still applies:
  - the Lua 5.0 rules (no `#`, `%`, `string.match`, `select`; no closures over loop variables; at most 32 upvalues)
  - no `_G` (use `getglobal`/`getfenv(0)`)
  - a strict fake client
  - check ClassicAPI signatures
  - one commit per task, with a trailer naming the model.
- **Never called anywhere:** `BuyTrainerService`, `SetTrainerServiceTypeFilter` and `BuyMerchantItem`. The mail and auction rules from phases 3 and 4 are unchanged.
- **Pinned source:** LibCrafts-1.0 at commit `e0cc17e13307ac0fc4bfd469b1e4d145b9eb6194`.
- **Defaults:**
  - `settings.recipes = { tooltip = true, skillAhead = 25 }`
  - `settings.deals.recipe = true`
  - `settings.deals.paybackCrafts = 10`.
- **Storage:** `TaxTheFoolsDB.recipes[prof] = { trainer = {}, seen = {} }`, account-wide and created on demand.
- **Pass counts:** each task reports its actual count; the gate is 0 failed. Baseline 447 passed.

## Review Focus

1. **A recipe learned by its captured name that differs from the built-in name** (Turtle renames) must not show as unlearned when the product matches. Tested in Task 2.
2. **A pattern sold by a limited-stock vendor and listed on the AH:** the AH price is still considered, and the vendor cost is labelled limited. Tested in Task 2.
3. **A trainer window showing another profession's rows (or First Aid) and header rows:** nothing stored for them. Tested in Task 3.
4. **A pattern deal for a recipe every tailor on the realm already knows:** no deal. Tested in Task 5.
5. **The Learned view after adding Not learned:** phase 2's rows, sort and detail are unchanged. Tested in Task 4.

### Task 2: Pure recipe rules (`recipes.lua`)

**Files:** create `TaxTheFools/recipes.lua` (in the .toc after `craft.lua`) and `tests/test_recipes.lua`. Add the defaults above to `data.lua`, and the `TaxTheFoolsDB.recipes` table to `db.lua`'s init.

**Interfaces produced (spec §4):**
- `Recipes.Catalogue(prof, data, learnedDb, realmChars, items)`, where `items` is `TaxTheFoolsDB.items`, for name resolution
- `Recipes.Unlearned(catalogue, char, prof)`

- `Recipes.Payback(cost, profit)`
- `Recipes.PatternIndex(catalogue)`
- `Recipes.Crafters(realmChars, prof, entry, skillAhead)`
- `Recipes.ParseTip(lines)`
- `Recipes.IsPattern(name, itemType)`.

Tests use small inline `data` tables, not the generated file.

**Required tests:** the `recipes.lua` list in spec §7, plus Review Focus 1 and 2.
